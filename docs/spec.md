# M-Sense SQL 与取数能力组

维护本文作为当前功能规格。迭代中修改源码并通过 GitHub / Vercel 预览，最后按需统一导出离线文件和源码包。

## 层级

SQL 取数项是可复用的指标或维度定义；取数能力组保存业务目标、指标引用、维度引用与下钻组；分析模块引用能力组的固定发布版本。

主入口是取数能力列表。自定义能力与原有能力放在同一列表，使用相同的能力标题和卡片结构。此前单独放在列表外的两项也是能力组，不是独立 SQL 模块；已有用户数据保持，统一展示。

主路径：已有 / 新建能力 → 填写基础信息 → 在指标 / 维度区域新建 SQL → 自动解析、DS 修正 → 保存并返回能力组 → 整体试跑 → 核对 → 发布能力 → 分析引用并试跑。能力内 SQL 自动关联，不要求 DS 再到外部 SQL 库发布。

SQL 复用库收在可选的“SQL 复用管理”入口，只用于独立验证、发布和跨组复用。配置页显示流程导航，`/#/guide` 提供每一步的实际入口、保存对象和完成条件。

WHEN SQL 独立运行成功并核对发布，THEN 可以将这个版本加入已有能力组，或者新建并保存一个能力组后加入。已有引用显式切换版本，不能重复添加。能力组已有配置和已发布版本保持。

WHEN SQL 尚未独立发布，THEN 可以直接在新能力组或其已归属能力组中保存为能力内草稿，随整个能力组试跑与发布固定完整定义。跨多个能力组复用时先独立发布 SQL 版本。

WHEN SQL 维度加入空能力组，THEN 仍需选择至少一个指标来源，才能执行整体取数和分析。

WHEN 能力组试跑成功且结果已核对，THEN 发布能力组，在分析模块中显式选择此版本并配置分析思路。发布新版本不自动升级旧分析引用。

## 统一试跑面板

指标、维度的独立运行和整个能力组试跑共用页面骨架：标题和当前范围、已选指标 / 下钻维度、实验 ID、观测起止日期、取数计划、获取数据、任务状态、结果表、核对及发布入口。高级上下文参数按需展开。

能力试跑执行当前组的全部来源与独立 / 交叉下钻组合，每个组合生成一份真实 Dataset。独立 SQL 只执行当前取数项；维度独立运行展示实体映射和实际枚举。

参考页面：`https://msense.bytedance.net/analyst/capabilities/core_metrics_by_dimension/trial?target_id=22&metric=UserCntAll`。2026-10-21 实际打开并点击日期入口，核验标题、证据栏、实验和日期输入、取数计划与获取数据。未提交生产取数查询。截图只显示取数前态，结果区域沿用本工程已有表格、状态、快照和核对逻辑。

本原型复用现有执行与结果组件并对齐 M-Sense 交互；生产系统源码和服务未提供，不能声称已直接接入生产面板。

## SQL 与组合约束

保留自动解析、DS 名称 / Key / 类型 / 格式 / 精度 / 口径编辑、维度枚举标签与列映射。重解析保留人工设置，异步旧结果丢弃；来源或粒度变化需要复核。人工枚举不转换 SQL 原值。

保留四种已有 / SQL 指标维度组合和三种维度交叉来源。可下钻指标使用明确 SQL 模板位置。交叉组关联实际明细并联合分组，禁止从独立汇总推导。

SQL 或查询配置变化使当前取数失效，展示定义变化要求重新核对。空数据、权限不足、错误、错类型、实体重复或关联缺失不能发布。

## 运行与部署边界

Vite、原生 JavaScript、Lucide、sql.js。浏览器 Worker 执行生成的示例底表，存储键 `msense-composer-v2`。GitHub 保存源码，Vercel 部署可交互原型；生产 SQL 服务、权限、版本注册和模型服务尚未接入。

内置“优惠券支付分析 · 完整示例”：固定 ID `demo-sql-ability`，含 SQL 支付指标、SQL 消费分层和已有生命周期。真实示例 SQL 预先完成解析、独立运行、发布 v1、能力整体 / 两个单维 / 交叉运行、发布 v1 与分析。结果不是随机拼装；支付 GMV 对照组 7098、实验组 8286；结果行数 2 / 6 / 4 / 12。样例存于 `src/composer-demo.json`，初始化只补充缺少的示例，不重置用户草稿或分析引用。

SQLite 使用内联 WebAssembly 二进制，减少对浏览器 JavaScript 栈大小的依赖。旧离线 HTML 未自动更新，用户通过线上地址体验当前改动；最终需要时再导出。

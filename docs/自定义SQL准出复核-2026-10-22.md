依据：[m-sense 10月交付功能细节](https://bytedance.larkoffice.com/docx/TS5FdUcAooagIzxBRYAcT4SFnuh)，本次读取 revision 400；[当前功能规格](./spec.md)、[使用说明](./用户操作使用说明.md)、[增量规格](../.trae/specs/align-custom-sql-mmvp/spec.md)、[原验收清单](../.trae/specs/align-custom-sql-mmvp/checklist.md)，以及[在线 Demo](https://msense-sql.vercel.app/#/capabilities) 的实际操作。源码基线为 `870ef3c`。

## 判定

**最小范围和主流程可以进入评审；当前“产品文档 + Demo”暂不建议标记为研发准出。** 需要修正两处已复现的行为问题，并收口少量产品规则；不需要继续增加功能模块。

这里的“研发准出”指：研发和测试能够依据同一份产品规则实现、验收，关键操作的页面表现与规则一致。它不要求原型已经接入全部生产服务；生产上线仍需另行验证真实授权、执行和发布。

上次“原型全部验收通过”应限定为当时覆盖的路径。本轮发现的反例说明，“缺少变体不能发布”和“按最新展示核对”仍需补验，原清单的全勾选不能直接作为准出依据。

## 两处准出阻断

### 1. 已选择的独立下钻被静默遗漏，仍可发布

**复现：** 新建能力 → 使用完整“指标 × 维度”SQL 示例 → 保存返回 → 添加已有“生命周期”维度 → 校验 → 整体试跑 → 核对并打开发布确认。

**实际结果：** 页面有“消费力 × 城市 ID”和“生命周期”两个下钻组，证据栏显示 3 个下钻维度；校验无错误，计划只有 1 个任务，结果仅包含消费力 × 城市，没有生命周期结果。发布确认按钮仍可用。

**影响：** 分析师会误以为选中的下钻已全部验证。发布版本的配置与实际可消费结果不一致。

**最小修正：** 只允许提交有对应 SQL 或受支持模板的下钻。完整 SQL 无法承接的独立下钻，在添加时提示不可用；兼容已有草稿时，校验和发布必须拦截并定位缺少的 SQL。无需增加任意 SQL 自动改写或自动拼接能力。

**准出场景：** WHEN 已选下钻缺少可执行查询，THEN 不得显示“全部取数有效”或允许发布；用户补齐查询或移除该下钻后，才可继续。任务与结果应能逐一对应已选下钻。

依据：原文 [2.5.1 分组结构](https://bytedance.larkoffice.com/docx/TS5FdUcAooagIzxBRYAcT4SFnuh#doxcnRbOfi4ftprE7WbGidDbwte)；增量规格“没有对应 SQL 变体”场景。定位：[任务生成](file:///Users/bytedance/Documents/sql_creator/src/composer-engine.js#L207-L225)、[下钻校验](file:///Users/bytedance/Documents/sql_creator/src/composer-data.js#L319-L340)。

### 2. 展示配置修改后，可以核对旧展示并发布新定义

**复现：** 独立 SQL 成功试跑 → 在字段“更多”中启用订单核销率的“对照组比较指标显示为 —” → 返回取数验证页，不重新取数 → 勾选核对 → 发布。

**实际结果：** 同一条历史运行的对照组仍显示 `66.67%`，未显示 `—`；核对可勾选，发布成功，发布快照中的新展示开关为开启。

**影响：** 用户实际看到并核对的展示，与发布后的定义不同。虽然旧的核对状态被清除，但重新核对的对象仍是旧展示。

**最小修正：** 展示配置修改后，用既有 SQL 原始结果按当前展示规则重新渲染，再要求核对；保留历史运行快照。这样无需为了格式变化重复取数，也不增加配置表单。

**准出场景：** WHEN 仅展示定义变化，THEN 当前核对视图立即反映新格式，旧确认失效；核对视图使用的展示定义必须与将发布的定义一致。

依据：原文 [2.5.2 指标字段](https://bytedance.larkoffice.com/docx/TS5FdUcAooagIzxBRYAcT4SFnuh#doxcnP1lv7hoKOfHfLkJFbfLghd)明确“仅改展示，不改原始值”；当前规格明确“展示定义变化要求重新核对”。定位：[结果显示](file:///Users/bytedance/Documents/sql_creator/src/composer-ui.js#L282-L292)、[核对签名更新](file:///Users/bytedance/Documents/sql_creator/src/composer-ui.js#L785-L790)。

## 产品文档需要收口的内容

### 统一关键规则与验收状态

`docs/spec.md` 已被指定为当前事实来源，但“无变体时如何处理”和 Q01–Q04 等细节仍主要在增量规格里；增量规格还保留“后续获批后合入”的旧措辞。使用说明适合教用户操作，不能替代这些规则。

建议仅在当前规格补一张短规则表：变更类型、结果是否失效、是否重跑、是否重新核对、发布条件。把上面两个 WHEN/THEN 场景作为对应例子；增量规格保留溯源，验收清单重新打开“缺少变体不能发布”并补充“展示变更不重跑”的用例。

### 明确最小权限与输出约定

以下是原文或既有规格中仍未闭合的决策。缺少生产接口本身不构成前端设计阻断，但影响用户行为的选择不能全部留给开发临时决定。

| 事项 | 准出前最少写清什么 | 简化方式 |
| --- | --- | --- |
| 执行身份与底表授权 | 使用个人还是服务身份；按谁的权限校验；无权限时由谁处理、能否重试。 | 复用现有权限与申请入口，不新建授权中心。原文尚未给出最终选择。 |
| SQL 输出约定 | 分组身份、指标、维度、每行粒度、空值和重复粒度的有效性规则；正式规范在哪里维护。 | 沿用现有平台契约并给一份最小示例；明确 Demo 固定列名是否仅为适配约定。技术接口字段可由研发文档承接。 |
| SQL 标准与资源设置 | 编写规范的引用来源；本期额度由平台统一控制还是允许用户修改。 | 建议本期使用平台默认值，不增加超时/行数/重试表单；这是待确认的裁剪建议，原文仍保留资源设置条目。具体额度可后续资源评审确定。 |

“已知不合法输入不得执行”“权限不足不得绕过”“失败不得生成成功版本”等行为先写清；SQL 方言细则、接口参数和资源数字放入各自专业规范，不堆入产品页面。

### 收窄 Key 规则的适用对象

本轮还实测到：保存能力后，下钻组 Key 仍可直接编辑，不出现引用影响确认。能力/SQL 对象的 Key 有专门确认入口，两类行为不同；增量规格对字段与下钻 Key 的影响检查描述容易造成误解。

最小建议：能力和 SQL 的稳定 Key 保留现有确认；自动生成的下钻组 Key 在本期界面只读，业务用户调整组名称即可。若保留组 Key 编辑，则须明确影响范围与确认规则。原文对组合元信息允许选填，因此无需新增一整套组级版本管理。

## 可以继续删减，但不作为本轮阻断

- 完整 SQL 路径只突出其实际输出的维度与结果；独立维度映射和模板组合按需出现，减少重复理解“SQL 维度、下钻维度、下钻组”的负担。
- 常用字段保留名称、角色、类型、格式和口径；身份字段、绑定、低频元信息继续折叠。
- 同一页的“独立试跑 / 进入取数验证”和“整体试跑 / 查看结果”可逐步合并入口；无需为此重做页面架构。
- 保留一次清晰的“示例数据 / 本地版本”提示；部署、工程框架等说明移到开发说明，减少分析师页面上的解释性文字。
- 不补回已删除的执行条件、不新增参数表达式编辑器、不把待讨论的计算指标配置器纳入本期；SQL 中直接计算最终指标即可。

## 最小准出动作

1. 修复两处阻断，并验证“缺少下钻 SQL”和“只改展示后核对发布”两条反例。
2. 把有效的状态、发布与失败规则收回当前规格，校正原验收结论；明确下钻组 Key 的简化处理。
3. 确认执行身份、引用的输出/SQL 规范及资源配置入口范围。实现细节与额度数字可由研发规范承接。

完成后即可按最小范围重新判定研发准出。无需把上述动作扩展为更多管理页面，也无需把生产服务尚未接入等同于“产品方案必须全部重做”。

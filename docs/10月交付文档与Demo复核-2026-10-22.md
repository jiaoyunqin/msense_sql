### AI 追问的最小验收场景

1. WHEN 在一个已完成报告中发问，THEN 回答只使用该报告的已有数据与结论，能定位所用证据。
2. WHEN 同一会话继续问“那城市分层呢”，THEN 沿用此前问题与该报告上下文；报告没有城市数据时说明缺失。
3. WHEN 刷新或重新打开同一报告，THEN 原问题和回答仍可查看；其他报告不混入这段对话。
4. WHEN 问题超出报告数据范围，THEN 不自动新建查询或改写原报告。
5. WHEN 回答生成失败，THEN 保留问题并允许重试，不伪造成功回答。

前四项来自原文明确范围，第五项为建议补充的失败验收细节。当前“分析输出”是基于示例输入生成的数值描述，不能替代这些交互。

## 目录存在本地与线上差异

本次线上目录已有来源、状态筛选及自定义能力的版本、更新时间。但九项原预置 RPC 没有完整的版本与更新时间展示；“已发布”筛选仍把这些没有正式发布元信息的 RPC 一并显示。

隔离浏览器中，线上“已发布”筛选显示 10 项，即九项 RPC 和已发布自定义示例。本地新目录实现显示 1 项；PreAA 标明“版本未提供，更新：—”，并补了业务目标筛选。**这是已在本地处理、尚未更新线上预览的差异，不宜再次增加一套目录功能。**

本轮还发现“内置 SQL”目录筛选没有条目，内置支付、核销 SQL 位于 SQL 复用库。按照最新目录裁剪，SQL 子项不自动升格为目录模块，也明确撤回了额外包装模板模块的提案，因此不能仅凭这个空筛选判定缺少两个目录能力。内置 SQL 的查看与复制入口实际存在：本轮打开支付来源，SQL 只读，复制后生成可编辑新 SQL，稳定 Key 尚未分配。

## 生产交付边界与建议顺序

当前 SQL 在浏览器示例底表执行；配置、发布版本和记录保存在当前浏览器。正式取数服务、服务端参数目录、身份与底表授权、版本注册和模型服务尚未接入。正式业务试用需要验证这些接口及跨会话数据保存，但不需要为每个后端依赖增加一个产品页面。

建议按以下顺序收口：

1. **补 AI 追问的最小报告内交互与持久会话**，明确首期仅使用报告已有数据。
2. **完成现有目录本地迭代的验收**；明确本期预置能力名单，补其只读元信息和必要试跑记录/有效结果。
3. **确定执行资源策略、SQL 输出规范和执行身份**。若使用平台默认资源，直接修订交付条款，避免为轻量版本新增无必要设置。
4. **同步交付规则、旧缺陷状态及配置复用操作说明**；区分 Demo 验收和生产接入验收。

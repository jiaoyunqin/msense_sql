# 取数验证与发布记录渐进展示 Spec

状态：已批准，实现、本地逐项验收及本地预览更新完成。变更编号：`reveal-validation-and-publication-progressively`。日期：2026-10-22。

## 为什么

用户截图中的能力配置页在尚未填写配置、没有试跑及发布记录时，已经展示两张大面积空卡片。新建时应让用户聚焦配置，后续操作随条件满足而出现，历史信息在实际产生后按需查看。

## 变更内容

- 没有试跑记录时，取消配置页底部的“取数验证”空卡片；满足配置条件后，通过页头“整体试跑”进入原取数验证浮层。
- 有试跑记录时，在配置内容之后显示一行紧凑验证摘要，提供“查看结果”，详细结果仍在原浮层查看。
- 没有发布版本时，不展示“发布记录”；有版本后，以默认收起的记录区展示版本数量、最新版本及发布时间，展开后查看原版本明细。
- 页头及浮层中的发布入口随当前结果核对通过而出现，保留原发布确认与校验。
- 独立 SQL 页面沿用同样的试跑入口及发布记录展示规则；能力内 SQL 仍保存返回能力组整体试跑。
- 继续采用现有配色、字号、边框、圆角与按钮，不引入步骤导航或新的页面。

上述入口显隐及紧凑布局属于本次设计提案；用户已明确的问题是“未填写任何信息就展示取数验证和发布记录”。

## 影响

- 受影响能力：能力配置页、独立 SQL 配置页、取数验证浮层中的发布入口、发布记录。
- 主要代码：`src/composer-ui.js` 中 `renderAbility`、`renderItem`、`versionsHTML`、`renderTrial`、`updateValidity`、相关事件处理。
- 样式：`src/composer.css` 中新增验证摘要与记录折叠布局，沿用现有样式变量。
- 状态依据：复用 `src/composer-data.js` 的 `abilityIssues`、`itemIssues`、当前运行及签名，以及 `src/composer-engine.js` 的发布校验，不另存一套流程状态。
- 获批后把有效规则同步到当前事实来源 `docs/spec.md`；本轮提案仅创建本目录的三份规格文件。
- 本变更与 `consolidate-retrieval-module-catalog` 的目录标签、筛选改动独立；实施时读取最新共享文件并保留其修改。

## 设计与状态规则

### 展示位置

新建和未完成配置时，页面保留基础信息、指标、维度及原保存／配置复用操作。页头操作区下方允许一行次要文字说明当前下一步，例如“填写能力说明后继续配置”。提示来自现有配置检查的首个待补项，不展示整块警告。

有记录后，配置内容下方按顺序显示验证摘要和可折叠发布记录：

```text
能力名称                         保存草稿  整体试跑  [发布能力]
基础信息
指标
维度

取数验证  已核对 · 10-22 14:30                    查看结果
▸ 发布记录 · 2 个版本    最新 v2 · 10-22 14:35
```

“发布能力”仅在当前结果已满足发布条件时出现。验证摘要没有原空卡片的大标题、空正文与大段留白；窄屏可以自然换行。有记录时不再出现“还没有试跑记录”“暂无发布版本”。

### 状态依据

| 条件 | 定义 |
| --- | --- |
| 配置可试跑 | 能力组或 SQL 通过已有静态配置检查；能力组至少选中一个实际指标。SQL、输出、参数来源及已启用下钻满足已有要求。 |
| 有试跑记录 | 当前对象的 `runs` 非空，包括运行中、成功、空结果、失败及历史记录。仅打开或关闭浮层不产生记录。 |
| 当前取数有效 | 按已有当前运行和查询签名规则判断，运行成功、非空且适用于当前查询配置及上下文。 |
| 当前已核对 | 当前有效运行的核对签名匹配当前定义；仍遵守已有正常场景与完整结果校验。 |
| 可发布 | 已有发布校验没有阻断项，且当前对象允许发布。 |
| 有发布记录 | 当前对象的 `versions` 非空，不以已保存、有 Key 或完成试跑代替。 |

“配置可试跑”只检查配置定义，不执行 SQL、不请求数据；实验 ID、观测时间及参数实际值仍在浮层填写和校验。首次试跑仍按现有规则自动保存并生成稳定 Key。没有保存时间或 Key 不单独阻止首次进入试跑。

维度为可选配置：仅整体取数可以进入试跑；已配置维度或交叉时，检查其完整性，不要求用户为了出现入口新增维度。完整 SQL 自带单维／交叉粒度仍按原规则使用。

| 页面状态 | 页头试跑／查看入口 | 页头及浮层发布入口 | 配置页验证摘要 | 发布记录 |
| --- | --- | --- | --- | --- |
| 新建或配置未完成，无记录 | 隐藏试跑，保留保存及一行下一步提示 | 隐藏 | 隐藏 | 隐藏 |
| 配置可试跑，无记录 | 能力“整体试跑”；独立 SQL“进入取数验证” | 隐藏 | 隐藏 | 隐藏 |
| 已产生运行，尚未核对或运行异常 | 配置可试跑时保留原试跑；配置不完整但有记录时提供“查看验证” | 隐藏 | 显示实际状态及查看入口 | 仅有版本时显示 |
| 当前结果已核对且可发布 | 保留原试跑入口 | 显示原发布按钮 | 显示“已核对” | 仅有版本时显示 |
| 首次发布成功 | 按当前配置与记录条件展示 | 继续按原发布校验决定，不增加新的版本规则 | 保留 | 新增默认收起的发布记录 |
| 查询修改或展示修改后 | 按当前配置与记录条件展示 | 条件失效时隐藏 | 分别显示“需重新试跑”或“需重新核对” | 保留已有版本 |

表中页头规则适用于可编辑能力及独立 SQL。能力内 SQL 保留“保存并返回能力组”，不新增独立发布步骤；内置及归档对象保留原只读、查看历史和允许的试跑行为，不因入口显隐放开发布或编辑权限。

## 新增需求

### Requirement: FR-01 无记录时不展示历史区块

系统 SHALL 按真实试跑记录及发布版本分别决定两个区块的存在。没有记录时不渲染对应标题、边框、空态正文或预留高度。

#### Scenario: 打开新建能力

- **WHEN** 用户进入新建能力，尚未选择指标，没有试跑和发布记录
- **THEN** 页面展示配置及保存操作，底部没有取数验证或发布记录空卡片，页头不提前展示试跑及发布按钮。

#### Scenario: 保存未完成草稿

- **WHEN** 用户仅填写基础信息并保存，没有实际试跑或发布
- **THEN** 按原规则生成稳定 Key，但不会因此显示验证摘要、发布记录或认定配置可试跑。

#### Scenario: 打开未发布的独立 SQL

- **WHEN** 当前 SQL 没有发布版本
- **THEN** SQL 页面不展示发布记录区；语法解析不产生试跑记录或发布记录。

### Requirement: FR-02 按当前配置提供下一步操作

系统 SHALL 在配置可试跑时提供原试跑入口，在可发布时提供原发布入口。显隐条件使用已有校验，不以“填写过”“保存过”或手动步骤标记替代。

无记录且配置未完成时，页头动作附近以次要文字显示一个待补项；输入期间不自动展开红色错误清单。满足条件后，该提示退出，试跑按钮在原操作区出现。

有历史运行但当前配置不完整时，SHALL 保留查看验证的入口，允许读取历史记录；获取数据仍执行原配置校验，具体错误在浮层显示。直接路由及目录入口也继续使用原校验，显隐不替代执行和发布门禁。

#### Scenario: 仅填写名称和说明

- **WHEN** 用户尚未选择实际指标
- **THEN** 不提供整体试跑或发布，次要提示指向补充指标。

#### Scenario: 完成可执行配置

- **WHEN** 用户选中可用指标，SQL、字段、参数绑定及已配置下钻满足原检查
- **THEN** 页头出现“整体试跑”，无需先填写浮层中的实验及日期；底部仍不显示空验证区。

#### Scenario: 无维度的整体配置

- **WHEN** 用户仅配置能产出整体结果的有效指标，没有添加维度
- **THEN** 可以进入整体试跑，不要求先新增下钻。

#### Scenario: 尚未核对或核对被撤销

- **WHEN** 当前结果成功但尚未核对，或用户取消核对
- **THEN** 配置页及浮层隐藏发布入口；核对通过且原发布检查无阻断项后立即显示，无需刷新。

#### Scenario: 进入后配置校验失败

- **WHEN** 用户通过历史查看、原目录入口或旧试跑链接进入浮层，点击获取数据时当前配置有问题
- **THEN** 浮层给出已有具体错误，不绕过校验、不创建发布版本。

### Requirement: FR-03 有记录后显示紧凑验证摘要

系统 SHALL 在能力第一次实际试跑产生记录后显示紧凑摘要，包含“取数验证”、真实状态、该记录时间及“查看结果”。完整结果、全部历史、执行 SQL及核对操作仍由原浮层承载。

优先展示适用于当前配置的有效运行，否则展示最近一条实际运行并标明它与当前配置的关系。状态应区分运行中、成功待核对、已核对、空结果、失败、权限不足、超时，以及查询修改后的需重新试跑或展示修改后的需重新核对。历史成功不等于当前已验证，时间必须对应所展示记录。

独立 SQL 本轮继续通过原页头及浮层查看运行记录，不新增第二套结果摘要。

#### Scenario: 第一次试跑失败

- **WHEN** 实际试跑产生失败记录，用户关闭浮层
- **THEN** 配置页出现失败状态及查看入口，即使没有成功结果也可继续查看和修正。

#### Scenario: 只打开浮层

- **WHEN** 用户没有点击获取数据，直接关闭浮层
- **THEN** 不新增摘要或记录，原表单内容、滚动位置与焦点按原交互恢复。

#### Scenario: 修改当前查询

- **WHEN** SQL、计算、指标引用、下钻或上下文改变，使查询签名失配
- **THEN** 旧记录保留，摘要显示需要重新试跑，发布入口隐藏；不沿用旧核对。

#### Scenario: 只修改展示定义

- **WHEN** 指标名称、格式、精度或整体展示开关改变，但查询签名仍有效
- **THEN** 按原规则保留原始数据，摘要显示需要重新核对，浮层结果应用最新定义，重新核对前不展示发布入口。

### Requirement: FR-04 发布后按需展开记录

系统 SHALL 在至少一个实际发布版本存在时显示默认收起的发布记录。收起行包含“发布记录”、真实版本数量、最新版本号及其发布时间；没有对应时间时使用已有缺失值展示，不补造。

展开后沿用原版本明细，按版本倒序显示版本名称、操作、操作人、时间、查看快照及原有分析／关联操作。折叠切换不触发发布、分析或关联。

首次出现及切换对象后默认收起；同一对象编辑、保存、核对或刷新局部内容时保持用户本次已展开状态。浏览器重载后可以恢复默认收起，不新增持久化折叠字段。

#### Scenario: 首次发布成功

- **WHEN** 发布确认通过并实际创建 v1
- **THEN** 对应配置页出现收起的“发布记录 · 1 个版本”，展示 v1 及真实发布时间。

#### Scenario: 查看旧版本

- **WHEN** 用户展开已有多版本的记录区并点击查看快照
- **THEN** 显示所选固定版本，继续保留原分析使用或 SQL 关联操作。

#### Scenario: 发布失败

- **WHEN** 发布失败，没有新增版本
- **THEN** 没有版本的对象仍不显示发布记录；有旧版本的对象保留原数量、内容及本次展开状态，按原流程允许重试。

#### Scenario: 已发布能力被编辑或归档

- **WHEN** 当前草稿改变或对象被归档
- **THEN** 已有发布记录仍可查看；原固定快照及分析引用不变，操作继续遵守原来源与归档权限。

## 修改需求

### Requirement: 统一浮层与状态即时同步

系统 SHALL 继续使用现有取数验证浮层，保留证据范围、上下文、取数计划、任务、结果、SQL、核对及发布确认。页头入口和验证摘要始终打开同一对象的同一浮层。

配置输入、指标勾选、维度调整、SQL 解析、核对切换、运行结束、发布成功／失败及关闭浮层后，SHALL 更新相关操作及摘要。不能依赖手动刷新，也不能为了显隐重建正在编辑的表单而丢失光标、输入内容、选择或滚动位置。

折叠标题支持键盘操作及明确的展开状态；入口出现不主动抢焦点。浮层中的发布入口退出时，如果焦点落在该入口，应移到邻近可用操作；关闭浮层后原入口已不存在时回到合理的页头操作。

#### Scenario: 配置条件在输入中变化

- **WHEN** 用户补齐最后一个配置缺项，或取消最后一个实际指标
- **THEN** 试跑入口立即出现或退出，表单输入和光标保持，已有历史查看入口及发布记录按各自数据条件保留。

#### Scenario: 返回配置页

- **WHEN** 用户在浮层完成试跑或核对后返回配置
- **THEN** 立即看到最新摘要及正确的发布入口，原配置与上下文保持。

## 移除需求

### Requirement: 两个历史区块始终可见

**原因**：没有发生对应操作时，大面积空卡片提前占用配置页空间。

**迁移**：撤除无记录时的占位展示；有记录的对象使用紧凑摘要或可折叠明细。不删除或重建历史数据，不改发布快照、稳定 Key、查询／核对签名、SQL 归属及分析引用。

## 范围约束

本轮只调整入口时机与历史展示，不改变自由编辑流程、试跑执行逻辑、发布门禁和版本规则，不新增向导、状态总览、历史页面或详情抽屉。继续维护现有工程及预览，不额外生成离线 HTML 或源码压缩包。

# 取数能力载入入口收拢 Spec

状态：用户已批准（含设计假设 A／B／C），实现及独立验收完成；17／17 验收项通过，验收发现的任务 5 已由实现代理修复并独立复验，本地预览已打开。变更编号：`consolidate-ability-reuse-entry`。日期：2026-10-22。

## 为什么

独立 SQL 复用管理和另存取数配置提供了重复的复用入口。按照用户本次要求，复用统一为在能力配置页载入已有完整取数能力，保留当前编写、保存草稿、试跑和发布链路。

## 变更内容

- 删除独立“SQL 复用管理”入口及其独立管理页面。
- 完全删除“复用取数配置｜载入已有取数配置｜保存取数配置”栏，包括能力配置、SQL 配置、系统能力展开明细和试跑浮层中的该栏。
- 在能力配置页原“保存草稿”按钮紧邻左侧增加“载入已有取数能力”。
- 新按钮直接读取已保存的完整取数能力，不再读取另存的取数配置列表。
- 保留现有目录卡片、来源标签／筛选、基础信息、指标／维度编辑、渐进试跑／发布入口及记录展示。

## 影响

- 受影响能力：复用入口、完整能力载入、旧复用管理路由、相关说明。
- 主要代码：`src/composer-ui.js`、`src/main.js`、`src/retrieval-configs.js`；`src/composer.css` 和 `src/prototype.css` 仅清理失去用途的复用栏样式。
- 规格同步：任务 1 将已获批规则合入 `docs/spec.md`，替代“SQL 独立复用管理”和“保存／载入取数配置”入口规则。
- 保留原浏览器存储、能力和 SQL 对象、稳定 Key、发布快照、历史记录及分析引用；不批量删除旧 SQL 或已保存取数配置数据。
- 本轮不修改 SQL 方言、计算、参数绑定及真实执行规则，不增加新模板库、分类、权限或发布步骤。
- 验收补充修复：`src/composer-engine.js` 的维度过滤 SQL 包装在闭合括号前换行，避免尾部行注释吞掉包装语法；不改变 SQL 方言、绑定或过滤语义。

## 依据与设计假设

用户明确要求：

1. 删除单独的“SQL 复用管理”。
2. 完全删除整条取数配置复用栏。
3. 在“保存草稿”左侧增加“载入已有取数能力”按钮。

两张截图分别对应目录底部独立管理区和能力配置中的复用栏。当前代码还在 SQL 页、系统卡片和试跑浮层复用了相同栏，因此删除范围覆盖这些重复位置。

以下为用户已一并批准的最小规则，不再作为待确认假设：

- **设计假设 A**：可载入对象为已保存、未归档且具备完整可读取定义的取数能力；有版本时使用最新已发布版本，没有版本时使用已保存草稿。不增加版本选择器。
- **设计假设 B**：载入替换当前能力的取数内容，保留当前基础信息和身份，不另建一个能力、不跳转编辑来源。已有取数内容被替换前确认一次。
- **设计假设 C**：本期系统 RPC 只有固定样例、没有可复制的完整 SQL 定义，不自动转成自定义 SQL；载入仅提供实际可复用的完整能力。

已有目录收拢和渐进发布规格的功能已经实现，本次是新的复用入口变更，不重新执行其未相关任务。

## 新增需求

### Requirement: 能力配置页提供唯一载入入口

系统 SHALL 在新建／编辑能力的页头操作组中，将“载入已有取数能力”放在原“保存草稿”紧邻左侧，采用已有次要按钮样式，不重排整个页面。

该入口仅用于可编辑的能力草稿。SQL 编辑页、系统 RPC 选择区、目录和试跑浮层不新增同名入口；运行中、已归档或只读对象不允许载入。

#### Scenario: 从新建能力开始复用

- **WHEN** 用户打开新建能力页面
- **THEN** 原“保存草稿”左侧出现“载入已有取数能力”，页面没有独立复用栏。

### Requirement: 从实际取数能力选择来源

系统 SHALL 点击按钮后复用现有选择弹层，显示可载入能力的名称、说明及本次取用的版本或“已保存草稿”，支持名称／Key 搜索。排除当前对象、未保存草稿、已归档对象及无完整可读取定义的对象；不要求能力另存为复用配置。

有发布版本的来源读取最新已发布快照，即使来源有未发布修改，也不静默使用该修改。无发布版本的已保存来源读取当前草稿，允许未完成配置被载入，但继续按现有检查提示待补项。

无可用能力或搜索无结果时显示简短提示；取消或关闭不修改当前草稿。选择失效、来源删除或定义无法读取时提示原因，保留当前内容，不只载入一部分。

#### Scenario: 选择已有发布能力

- **WHEN** 来源能力已发布 v2，并有未发布修改
- **THEN** 选择项明确显示使用 v2，载入 v2 的完整取数定义；源草稿和源版本不变。

#### Scenario: 来源仅有已保存草稿

- **WHEN** 选择没有发布版本但已保存的能力
- **THEN** 载入该草稿并明确标识其未发布状态，缺项由原配置提示处理，不把它视为已验证。

### Requirement: 将完整取数内容载入当前草稿

系统 SHALL 载入指标定义、实际 SQL、输出字段和人工修正、参数来源绑定、维度来源、独立／交叉成员、启用状态、拆解条件和整体展示设置。

保留当前能力 ID、已有稳定 Key、名称、说明及固定业务目标；新建能力尚未保存时 Key 继续为空，首次保存才生成。保留当前实验 ID、观测时间和运行上下文，载入不主动取数。

自定义 SQL 复制为当前能力内草稿并重建内部引用，避免修改来源能力或违反未发布 SQL 只能归属一个能力的规则。内置来源保留合法固定版本引用和只读约束。字段 Key、人工指标定义、枚举和原生类型保持；维度成员及拆解条件随重建引用正确关联。

目标存在指标、SQL 或维度配置时，载入前提示将替换当前取数内容，确认后才整体应用。空配置不多加确认。载入后仍由“保存草稿”保存，不增加保存配置或另存副本步骤。

不承接来源的试跑结果、核对状态、发布版本、归档状态和操作历史。当前目标的既有发布快照、历史试跑和分析引用保留；查询／展示变化沿用现有签名规则要求重新试跑或核对。

#### Scenario: 替换已有取数内容

- **WHEN** 用户在已配置指标和维度的能力中选择另一能力并确认载入
- **THEN** 当前取数内容被完整替换，基础信息和标识保持；原发布版本仍固定，不自动更新分析引用。

#### Scenario: 取消替换

- **WHEN** 用户取消替换确认或关闭选择弹层
- **THEN** 当前草稿、SQL、维度、上下文及历史记录保持原值。

#### Scenario: 新建能力载入后保存

- **WHEN** 空的新建能力载入已发布能力后点击“保存草稿”
- **THEN** 为当前能力及新复制的 SQL 分配新稳定 Key，来源 Key 和版本不变；可以继续编辑并按原规则试跑、核对和发布。

## 修改需求

### Requirement: 复用发生在完整能力配置中

系统 SHALL 以已有完整能力为复用单位，当前能力内继续支持选择已有指标、编辑／复制 SQL 和配置维度。SQL 子项不再需要通过独立复用管理页创建或发布才能完成能力配置。

现有取数能力目录保持“新建取数能力”入口、原卡片及展开明细。试跑浮层继续保留证据、上下文、取数计划、结果和核对；删除复用栏后不留下空容器或额外间距。

#### Scenario: 载入后修改 SQL

- **WHEN** 用户修改载入后的能力内自定义 SQL
- **THEN** 修改仅作用于当前能力；原能力、原 SQL 和原发布快照保持。

## 移除需求

### Requirement: 独立 SQL 复用管理

**原因**：用户要求删除该独立模块，复用入口收拢到完整取数能力。

**迁移**：删除目录“SQL 复用管理／管理可复用 SQL”区块及其他页面／说明中的独立管理链接；旧 `#/items` 链接返回取数能力目录，不再渲染管理库。现有 SQL 数据不删除，当前能力引用及能力内 SQL 编辑链接继续可用。

### Requirement: 独立保存和载入取数配置

**原因**：用户要求整栏完全删除，改为直接载入已有取数能力。

**迁移**：删除所有“复用取数配置”“载入已有取数配置”“保存取数配置”按钮、栏和旧配置管理弹层入口。旧 `retrievalConfigs` 数据保持但不作为新载入源；新载入流程不新增该集合的记录。只清理失去用途的代码和样式，不删除其他共享能力。

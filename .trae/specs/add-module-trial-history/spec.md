# 模块内试跑记录 Spec

状态：已批准并完成，任务 1 至 4 与 25 项验收通过。用户随后明确要求更新 Vercel，按该授权推送部署。变更编号：`add-module-trial-history`。日期：2026-10-22。

## 为什么

当前能力已保存多次试跑，但配置页只展示一行验证摘要，历史入口主要在取数验证浮层中，用户不容易按实验和时间找回某次结果。补充模块内记录入口，让 DS 在配置、试跑和发布过程中回看证据，并明确历史成功与当前配置验证的区别。

## 变更内容

* 在能力配置页的取数验证摘要下方、发布记录上方增加默认收起的“试跑记录 · N 次”，首次实际产生记录后才显示。

* 展开后沿用截图的记录行结构，展示实验 ID、试跑时间、状态和查看入口，按最近试跑在前排列。

* 记录行打开现有取数验证浮层的只读记录视图，显示当次入参、取数范围、任务和结果快照。

* 记录归属于当前完整能力模块；同一模块的不同实验、不同草稿阶段记录保留，SQL 子项和其他模块的记录不汇入。

* 保留当前验证摘要、核对和发布规则。查看记录不修改当前上下文、不执行取数，也不生成用户侧报告。

本次位置、默认折叠和只读详情均已批准。用户已明确要求增加试跑记录，且“试跑记录仅属于当前模块，不进入用户侧报告列表”。

## 影响

* 受影响能力：完整能力配置页、能力取数验证浮层的历史选择和详情。

* 受影响代码：`src/composer-trial-records.js` 的纯读取契约；`src/composer-ui.js` 的 `renderAbility`、`refreshProgress`、`openTrial`、`renderTrial`、`abilityResults` 及记录选择事件；`src/composer.css` 的记录布局。

* 数据依据：复用当前能力的 `runs`，以及 `src/composer-data.js` 的当前运行、查询签名和核对签名。复用已有 `context`、`definition`、`modes`、执行结果及 SQL 快照，不另建报告对象。

* 既有约束：继承 `reveal-validation-and-publication-progressively` 的空区块隐藏、摘要和发布门禁；继承 `consolidate-ability-reuse-entry` 的目标历史保留及不复制来源历史规则。

* 既有相关变更均已完成。本变更补充记录的可发现性和当次详情语义，不重开此前任务。

* 已获批准，任务 1 已将有效规则同步到唯一功能事实来源 `docs/spec.md` 并实现共享纯读取 API；任务 2、3 负责配置页及浮层接入，验证证据记录在 `tasks.md`，验收清单由后续独立验收据实勾选。

## 设计与展示

### 位置

记录属于取数验证过程，放在配置内容之后，紧邻验证摘要；发布记录继续位于它下方。

```text
基础信息
指标
维度

取数验证  已核对 · 10-22 11:39                    查看结果
▸ 试跑记录 · 3 次
▸ 发布记录 · 2 个版本    最新 v2 · 10-22 11:45
```

展开示意：

```text
▾ 试跑记录 · 3 次

  [试跑图标] 实验 5629666                 已完成   查看 ↗
             2026-10-22 11:39:05
  [试跑图标] 实验 5629666                 已完成   查看 ↗
             2026-10-22 11:16:22
  [试跑图标] 实验 5467546                 失败     查看 ↗
             2026-10-21 20:08:10
```

示意中的实验、时间及数量只用于说明布局，实施时全部读取实际记录。

沿用现有字号、边框、圆角、按钮和蓝色试跑图标。折叠标题只显示名称和次数，避免重复验证摘要。展开后说明展示一次；长列表在记录区内滚动，不截断或删除记录，桌面高度可容纳约三行，窄屏自然换行。时间不能因省略而不可读。

### 范围

“当前模块”指当前完整能力的稳定内部身份，不以名称、实验 ID 或发布版本分组。改名、编辑和发布新版本后仍显示该模块自己的历史；另一个同名模块不共享记录。

本次新增配置页入口用于具有实际 `runs` 的完整能力，包括可读取的内置 SQL 能力和归档能力。归档或只读不妨碍查看历史，执行及编辑限制沿用已有规则。

独立 SQL 继续保留自身验证记录，能力内 SQL 继续保存返回能力组；本次不新增 SQL 编辑页记录区，也不把子项独立记录合并成模块整体试跑。分析模块已有分析试跑记录保持自己的范围。

预置 RPC 当前仅展示固定示例，没有持久化试跑任务；本次不将示例结果或“查看示例”次数补造为历史任务，其现有展示保持。

## 新增需求

### Requirement: FR-01 按模块归属读取真实记录

系统 SHALL 仅从当前完整能力的实际试跑集合读取历史，标题次数等于记录条数。一轮能力试跑是一次记录，轮内整体、独立维度和交叉任务是该轮的子任务；同一实验重复执行产生不同记录，不按实验 ID 去重。

保存草稿、解析 SQL、打开或关闭浮层、查看记录、切换结果及核对不增加次数。点击获取数据并由现有执行流程实际创建运行时才增加次数；入参校验未通过且尚未创建运行时不增加。

系统 SHALL 不将该历史集合写入用户侧报告列表、分析报告集合或报告数量，也不提供记录转报告、分享报告或报告发布入口。

#### Scenario: 同一实验试跑两次

* **WHEN** 当前能力对同一实验实际执行两轮取数，每轮有多个下钻任务

* **THEN** 历史增加两条，各自具有唯一运行身份及时间，标题增加两次，不按子任务数量或实验数量计数。

#### Scenario: 切换或复用模块

* **WHEN** 用户切换到另一能力，或从已有能力载入配置、复制出新能力

* **THEN** 只显示目标能力自己的记录；载入保留目标历史，复制的新能力没有来源历史。

#### Scenario: 查看历史

* **WHEN** 用户展开记录、打开详情并返回

* **THEN** 记录次数、当前草稿、上下文、核对及报告集合均不因查看改变。

### Requirement: FR-02 渐进展示并保持折叠状态

系统 SHALL 在当前能力没有记录时不渲染试跑记录的标题、边框、说明、空态或预留高度。第一次记录产生后，系统 SHALL 在验证摘要之后、发布记录之前显示默认收起的记录区；无发布版本时仍可独立显示试跑记录。

首次出现、切换模块及浏览器重载默认收起；同一模块编辑、保存、核对、运行状态更新和关闭详情后，保持本次展开状态。折叠状态只用于本次界面，不写入业务定义或生成草稿差异。

折叠标题支持键盘并暴露展开状态。记录数量和状态在实际运行开始、结束或失败后同步，无需刷新，也不重建配置输入而丢失光标、内容或页面滚动位置。

#### Scenario: 配置就绪但没有试跑

* **WHEN** 用户补齐配置，或仅打开试跑浮层而未获取数据

* **THEN** 页头按原规则提供试跑入口，配置页不出现试跑记录空区块。

#### Scenario: 首次试跑失败

* **WHEN** 现有执行流程实际创建记录并运行失败

* **THEN** 配置页仍显示“试跑记录 · 1 次”，默认收起，展开后可以查看失败原因。

#### Scenario: 展开后继续编辑

* **WHEN** 用户已展开记录，然后保存草稿或从记录详情返回

* **THEN** 列表保持展开和合理的滚动位置；切换模块或重载后恢复收起。

### Requirement: FR-03 用当次实验、时间和执行状态识别记录

系统 SHALL 沿用实际记录顺序，最近执行在前；新记录插入顶部，但不主动展开列表或抢焦点。旧记录顺序保持，同一时间的记录不因重渲染交换。

每行至少提供以下内容：

| 内容    | 读取和展示规则                                             |
| ----- | --------------------------------------------------- |
| 实验 ID | 当次记录的实验 ID，主文案为“实验 X”；不以运行 ID 代替实验 ID。缺失时显示“实验未记录”。 |
| 试跑时间  | 当次开始时间，展示可读日期及时分秒；缺失时显示“时间未记录”，不使用当前时间或模块更新时间补齐。    |
| 执行状态  | 来自当次实际执行状态，按下表映射，不使用当前验证摘要覆盖。                       |
| 查看入口  | 使用唯一运行 ID 定位当次记录；提供文字或可访问名称，不能只有无说明的箭头。             |

| 实际执行状态  | 记录行文案                    |
| ------- | ------------------------ |
| 运行中     | 运行中                      |
| 成功且非空   | 已完成                      |
| 执行返回空结果 | 空结果                      |
| 失败      | 失败                       |
| 权限不足    | 权限不足                     |
| 超时      | 超时                       |
| 旧记录其他状态 | 沿用已有准确文案；无法识别时显示“状态未记录”。 |

“已完成”只表示这次取数执行成功，不表示当前草稿已核对或可发布。草稿变化不会把历史行的“已完成”改成失败或“需重新试跑”；当前状态仍由原验证摘要解释。

#### Scenario: 当前查询已经修改

* **WHEN** 旧记录执行成功，但当前 SQL、下钻或上下文改变

* **THEN** 旧行保留“已完成”和原时间，当前摘要按原规则显示“需重新试跑”，不能据旧行状态开放发布。

#### Scenario: 历史元信息缺失

* **WHEN** 旧记录没有实验、时间或部分详情

* **THEN** 展示对应缺失提示并保留查看入口，不用当前草稿补造历史信息。

### Requirement: FR-04 在现有浮层查看只读的当次快照

系统 SHALL 从记录行进入现有取数验证浮层的只读记录视图。详情包含当次实验 ID、观测起止时间、其他已记录入参、取数范围、任务状态、结果表、实际执行 SQL 和错误；运行 ID 放在详情中用于区分重复试跑。

记录详情 SHALL 使用该运行已保存的定义、任务、字段和结果快照，不以当前草稿的实验、指标名称、下钻定义或展示格式替换。当前有效运行的“查看结果”和当前验证继续沿用原逻辑，可应用最新展示定义并重新核对；历史记录入口始终展示当次快照。

详情清楚标注“试跑记录”，入参只读；不提供获取数据、核对、发布或按历史参数重跑操作。允许查看当轮不同任务、结果和 SQL。需要继续试跑时，通过“返回当前验证”回到该模块现有验证模式；该入口仅在对象允许进入当前试跑时提供，并继续执行原门禁。

返回当前验证后使用进入历史前的当前上下文和配置，不载入历史参数、不自动取数。返回配置、关闭和 Esc 沿用原返回行为，并恢复触发记录入口的焦点、配置滚动和记录展开状态。

旧记录缺失定义时，可展示已存的上下文、任务、字段、数据和 SQL，并标明缺失部分；没有结果时展示对应状态或错误。不能用当前定义补齐后伪称当次快照，也不能因为详情缺项删除记录。

#### Scenario: 实验 A 的结果和当前实验 B

* **WHEN** 用户当前填写实验 B，点击实验 A 的历史行

* **THEN** 浮层展示实验 A 的当次入参和结果，实验 B 的配置不变；退出历史后当前验证仍使用实验 B。

#### Scenario: 修改展示定义后回看

* **WHEN** 用户修改当前指标名称、格式或精度，再打开修改前的记录

* **THEN** 记录详情按已存字段快照展示；返回当前验证后仍按最新定义核对，旧核对不会被查看动作恢复。

#### Scenario: 查看运行中或失败记录

* **WHEN** 用户打开已存在的运行中、空结果、失败、权限不足或超时记录

* **THEN** 展示该轮实际任务、已产生的数据和错误；运行中后续状态更新仍指向同一运行，不切换到另一轮。

#### Scenario: 目标记录不存在

* **WHEN** 查看入口指定的运行在当前模块中找不到

* **THEN** 提示“该试跑记录不存在”，保持当前配置，不静默打开其他记录或其他模块结果。

### Requirement: FR-05 保持记录生命周期与验证隔离

系统 SHALL 复用当前记录持久化方式，不因本次 UI 变更清空、重建、合并或自动删除旧记录。新轮次不覆盖旧轮次；改名、保存、发布、载入配置或归档后历史仍属于原模块。

查看和折叠 SHALL 不修改业务定义、核对签名、发布快照、固定分析引用或操作历史。记录查看身份与当前执行身份分开，不能把选择历史记录变成当前已验证状态。

页面重载中断本地运行时，继续按现有逻辑将该轮标为失败并显示中断原因；次数不增加，不留下永久运行中。关闭浮层但页面仍在执行时，仍由原执行流程更新同一记录。

本次不增加历史删除、筛选、比较、导出、跨模块历史中心或新保留期限。

#### Scenario: 发布和归档

* **WHEN** 用户发布新版本或归档模块

* **THEN** 原试跑历史保留并可只读查看；已有发布快照和分析引用不变，归档仍不能发起新试跑或发布。

#### Scenario: 最新一轮失败

* **WHEN** 同一查询的最新试跑失败，而更早记录曾成功

* **THEN** 两轮均可查看，当前验证继续遵守最新同签名运行规则，不回退到更早成功以开放核对或发布。

## 修改需求

### Requirement: 当前验证与历史记录入口职责明确

系统 SHALL 保留配置页紧凑验证摘要及“查看结果”，用于查看当前验证状态。摘要下的试跑记录用于按当次实验和时间查找历史，列表状态与摘要状态各自读取正确的数据来源。

能力浮层已有的历史切换入口 SHALL 使用同一模块归属、运行身份和快照规则；选择另一轮历史时进入同一只读记录视图，不出现历史结果配当前实验或当前定义的混合展示。详情可在原位置提供当前模块记录选择，不新增另一套历史存储或独立历史页面。

#### Scenario: 从已有浮层切换历史

* **WHEN** 用户从当前验证浮层的历史入口选择另一轮

* **THEN** 与从配置页记录行打开该轮的结果一致；返回当前验证后配置、上下文和原门禁保持。

## 移除需求

### Requirement: 历史仅能在结果浮层内发现

**原因**：已有多次试跑无法在模块配置页按实验和时间直接找到。

**迁移**：为完整能力增加折叠入口，并复用原浮层承载当次详情；保留所有既有运行身份、结果、版本及引用，不另建报告或结果页。

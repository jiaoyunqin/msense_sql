# 自定义 SQL 最小上线范围对齐 Spec

核对日期：2026-10-21。状态：用户确认的四类补齐已按简化规则完成原型实现与验收。详细验证状态见 tasks、checklist；生产前置仍待确认。

## 本轮简化执行规则

用户确认参数目录、完整 SQL、管理细节和配置细节全部执行，同时要求保持 Demo 功能与界面简洁。以下规则优先于首次核对时较完整的表单建议：

- 参数目录放在编辑器“可用参数”按钮中，按需展开，支持搜索和插入；解析后的绑定继续折叠，不新增专门配置页。
- 完整 SQL 可同时输出自定义指标和维度；字段角色确认后自动形成自身单维或交叉结果。复用原有保存、试跑、发布与分析链路，不要求先拆 SQL 或先独立发布。
- 下钻成员可来自完整 SQL 中已声明的维度字段，也可来自独立维度来源。直接查询的成员按输出同步；多选独立下钻仍分别取数，交叉必须由真实联合查询支持。
- 组合名称与 Key 自动生成，说明改为选填；Key、说明和查看 SQL 收在“更多设置”，不因未写组合说明阻断发布。
- 比较指标“—”展示收在字段“更多”；仅改变显示，不改 SQL 原值。
- 来源 / 状态筛选沿用目录工具栏；归档收在卡片“更多操作”；Key 修改和引用影响在需要修改时才显示。
- 保留真实参数、类型、粒度和版本校验。生产权限、SQL 标准、资源额度仍为待确认事项，不扩展成本轮新模块。

## 为什么

首次核对时，设计已包含自定义 SQL 的配置、解析、试跑、发布和分析引用主链路，但尚未完整覆盖 10 月交付文档中的必需细节。此次完成已确认的原型补齐，并保留会议依据、原型限制和仍未决策的上线前置事项。

### 已覆盖且应保留的现有能力

- SQL 指标和 SQL 维度可在能力组内草稿使用，随组试跑、发布；独立发布用于跨组复用，不是创建能力的前置步骤。
- 已有指标 × 已有维度、SQL 指标 × 已有维度、已有指标 × SQL 维度、SQL 指标 × SQL 维度，以及三类维度来源交叉。仅有汇总数据的来源不能凭空增加下钻。
- 实际执行联合 SQL 验证交叉结果；不从独立汇总拼出交叉分布，不静默求和修复重复粒度。
- 重解析保留仍有效的人工设置；来源或粒度变更需复核；SQL 或查询配置变更使当前试跑失效。
- 能力固定版本被分析引用，新发布版本不自动升级旧引用。

这些规则主要来自此前共同设计，不全部是 10 月 16 日会议逐条提出的要求；它们与本次最小范围兼容，不作为额外上线阻塞项扩张。

## 新增需求

### Requirement: SQL 编写前可发现上下文参数

系统 SHALL 在 SQL 编辑阶段提供可展开、搜索的可用上下文字段目录，展示 Key、名称、类型、含义及占位符用法；选择字段后在光标位置插入 `${key}`。可采用 `@` 唤起同一目录。编辑前目录和解析后绑定必须共用定义；原型目录标明本地示例，生产使用服务端目录。

#### Scenario: 从空 SQL 开始编写

- **WHEN** 分析师尚未输入任何 SQL，打开参数目录并搜索实验 ID
- **THEN** 可以看到可用字段及类型，选择后插入占位符，无需先成功解析 SQL。

#### Scenario: SQL 使用未知参数

- **WHEN** 解析得到目录中不存在的参数
- **THEN** 保留该参数并提示未绑定；允许改绑到兼容的已有字段，不自动创建上下文或代填运行值；未完成绑定不能试跑或发布。

### Requirement: 显式登记 SQL 变体与下钻定义

系统 SHALL 为能力提供明确的整体、单维、交叉 SQL 绑定。名称和 Key 自动生成，说明选填，均可在折叠设置中调整；组合成员来自已声明的 SQL 维度字段或独立维度来源，成员不重复，Key 在能力内唯一。完整 SQL 自动绑定自身输出成员，模板组合绑定实际生成的查询；必须能查看本次实际 SQL。

#### Scenario: 多选单维下钻

- **WHEN** 分析师选择消费力和生命周期两个独立下钻组
- **THEN** 分别运行各自绑定的 SQL 变体，得到两份结果；仅多选单维不生成交叉结果。

#### Scenario: 显式组合维度

- **WHEN** 分析师声明消费力 × 生命周期并绑定真实联合查询
- **THEN** 核对成员、输出和联合粒度后独立执行；成员少于两个、重复、未声明或 SQL 输出不匹配时阻止试跑和发布。

### Requirement: 自定义 SQL 目录、来源和归档

系统 SHALL 显示名称、Key、业务目标、说明、来源、发布与草稿状态、更新时间，并支持名称或 Key 搜索及来源、目标、发布状态筛选。来源分为内置 RPC、内置 SQL、自定义 SQL，标签分别采用蓝、绿、紫。

内置 SQL 允许只读查看、试跑和复制为自定义 SQL；内置 RPC 在共用目录中仅查看与试跑，不开放 SQL 编辑、复制或归档。自定义 SQL 允许编辑、试跑和归档。来源限制必须在操作处理处校验，不能仅依赖按钮隐藏。

归档前 SHALL 展示当前已有引用并确认；归档不删除定义、记录或固定版本。归档对象默认不参与普通列表和新增引用选择，已有固定引用仍可解析；相关归档状态可查看。

#### Scenario: 复制内置 SQL

- **WHEN** 分析师复制一个内置 SQL
- **THEN** 创建具有独立稳定标识的自定义草稿；原定义和已有版本不变，草稿经确认、试跑后才发布。

#### Scenario: 归档被引用的 SQL

- **WHEN** 分析师查看引用影响后确认归档
- **THEN** 对象进入已归档状态，不再用于新增选择；已有能力或分析的固定版本继续引用原定义。

#### Scenario: 已发布能力发生修改

- **WHEN** 已发布 vN 的能力产生尚未发布的定义变化
- **THEN** 目录显示当前发布 vN 及 `vN+1 草稿待发布`；仅运行试跑或查看记录不产生定义变更提示。

## 修改需求

### Requirement: 解析与人工配置支持完整 SQL 的指标和维度输出

系统 SHALL 接受分析师提供的完整只读 SQL，解析实际输出字段及参数，允许在当前主配置中将字段确认为指标、维度、身份或辅助字段，并编辑名称、Key、说明、类型和展示规则。数字类型不等于指标角色，推断仅作为可修改建议。

完整 SQL 的粒度须明确为整体、单维或交叉，并绑定对应定义；只执行已配置的变体。与当前模板生成模式并存时，不把完整 SQL 自动套用到所有下钻组，不要求为已经聚合出的维度另写实体映射 SQL，也不从交叉汇总推导其他统计口径的变体。

重解析继续保留同一输出仍有效的人工配置；角色、来源、粒度、绑定变化需重新复核。完整 SQL 原型使用本地执行约定；生产分组标识和数据契约待接口确认，不将原型要求的固定列名当作已经确定的生产规范。

#### Scenario: 直接粘贴单维指标查询

- **WHEN** SQL 输出实验分组、消费力、GMV，分析师将消费力确认为维度、GMV 确认为指标并绑定消费力变体
- **THEN** 可以按该单维粒度校验、试跑和发布，不触发“指标 SQL 不能有维度”的阻断。

#### Scenario: 数字编码维度

- **WHEN** SQL 输出数字型城市 ID，分析师将其角色改为维度
- **THEN** 保留数字原值，按维度参与粒度校验与下钻，不因数字类型强制作为指标。

#### Scenario: 没有对应 SQL 变体

- **WHEN** 用户增加下钻组但没有绑定完整 SQL，也没有可用模板生成对应查询
- **THEN** 明确提示缺少该变体；不从已汇总结果补造下钻数据。

### Requirement: 字段展示与发布完整性

系统 SHALL 校验指标的英文 Key、名称、说明、原生类型与展示格式完整，格式、精度及适用规则有效；维度和组合的 Key、名称、成员与 SQL 绑定有效。组合说明选填，不新增发布阻断。

系统 SHALL 支持字段级“对照组比较指标显示为 —”配置，仅作用于选中的比较指标。普通基值指标继续显示原值。格式、单位、精度、空值与比较展示仅影响显示，不改 SQL 原值、数据集或计算结果；展示定义变更要求重新核对。

#### Scenario: 对照组比较指标

- **WHEN** 一个 SQL 输出的比较指标启用了对照组“—”展示
- **THEN** 对照组该单元格显示“—”，实验组按格式显示；普通 GMV 单元格仍显示数值，快照保留全部原值。

#### Scenario: 缺失字段定义

- **WHEN** 指标缺说明或格式，或组合维度缺有效 Key、合法成员或 SQL 绑定
- **THEN** 发布被阻止并定位待补配置，不能仅凭运行成功发布。

### Requirement: 基础信息与稳定 Key

系统 SHALL 在能力组校验名称、英文 Key、平台业务目标枚举、负责人邮箱前缀和说明。SQL 子项沿用当前层级关联，不重复要求业务目标等能力信息。

首次显式保存后，能力及 SQL 对象的 Key SHALL 保持稳定，改名称不改 Key。手动修改通过显式入口展示受影响的草稿引用、发布版本和分析引用，要求二次确认后才更新当前草稿；取消不改变定义。历史发布版本和已固定引用不自动迁移。字段或下钻 Key 变化同样必须检查成员绑定与引用影响。

#### Scenario: 改名称

- **WHEN** 分析师修改已保存能力的中文名称并保存
- **THEN** 稳定 Key 保持原值。

#### Scenario: 显式改 Key

- **WHEN** 分析师请求修改已保存对象的 Key
- **THEN** 展示引用影响并二次确认；确认后重新校验当前草稿，旧发布快照和分析引用保持固定。

### Requirement: 试跑与版本发布沿用现有链路

系统 SHALL 保留 SQL 独立试跑与能力整体试跑的共用面板，展示范围、上下文、任务、实际 SQL、结果、快照和核对。试跑记录明确仅属于当前配置对象，不自动进入用户侧报告列表。

发布版本 SHALL 固定完整定义，并记录版本号、操作、操作人和时间。能力内 SQL 草稿可随能力整体发布；跨组复用继续采用独立发布版本。SQL 或查询配置变化使当前验证失效；空数据、失败、权限不足或不合格结果不能发布。发布失败不创建假版本，允许保留草稿后重试。

#### Scenario: 能力整体发布

- **WHEN** 当前所有已配置变体试跑合格且全部结果已核对
- **THEN** 可以发布能力固定版本供分析显式引用；未配置的潜在组合不自动加入本次取数计划。

#### Scenario: 发布注册失败

- **WHEN** 发布注册失败
- **THEN** 不增加版本号或成功记录，保留草稿和失败反馈，后续可重试。

### Requirement: 原型验收与生产上线条件分别判定

系统 SHALL 明确当前本地示例执行和本地版本的边界。原型展示授权、额度和失败场景不等于生产接入完成。

生产发布须按已确认方案校验数据源授权，使用平台维护的上下文字段、正式 SQL 校验与执行、持久化记录及版本注册。授权未通过、标准校验未通过或注册未成功时不能显示生产发布成功。具体权限身份、禁用规范、额度和依赖检查对象不得在缺少决策时擅自确定。

#### Scenario: 本地原型发布

- **WHEN** 浏览器内示例 SQL 核对后创建本地版本
- **THEN** 明确显示本地状态，不据此声称 SQL 已进入生产取数或正式分析注册。

#### Scenario: 生产数据源无授权

- **WHEN** 正式服务按确定的执行身份检查到底表未获授权
- **THEN** 返回可定位的授权问题并阻止执行或发布；不切换其他身份绕过检查。

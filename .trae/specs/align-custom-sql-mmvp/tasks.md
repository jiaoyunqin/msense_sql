# 自定义 SQL 最小范围对齐任务

用户已确认四类补齐全部执行，并要求简化界面。任务 1–7 已完成原型实现与验收；生产服务开发与上线不包含在这些任务中。

- [x] 任务 0：完成三份飞书资料与现有设计的覆盖核对。
  - [x] 读取智能纪要、逐字稿和交付细节，记录版本及相关时间点。
  - [x] 对照 `docs/spec.md` 与当前路由源码，区分已覆盖、部分覆盖、缺失及待决策事项。
  - [x] 输出覆盖矩阵、增量需求、实施任务与验收清单。

- [x] 任务 1：将获批范围同步到当前功能规格。
  - 将本 Spec 已确认的规则合入 `docs/spec.md`，保持单一当前事实来源。
  - 明确完整 SQL 变体与现有模板组合的并存方式，以及稳定 Key、来源、归档和记录的共享定义。
  - 对已有草稿、固定版本和引用采用兼容默认值；不清空浏览器工作区或重写历史快照。
  - 验证：两份规格不存在相互冲突的有效规则，Q01–Q04 保留明确待确认状态。

- [x] 任务 2：补 SQL 编写前的参数目录。
  - 编辑器提供可展开、搜索的全部可用参数目录，展示名称、Key、类型、含义和用法。
  - 选择字段在光标位置插入占位符；如采用 `@`，使用同一目录和插入规则。
  - 编辑前目录、解析后绑定和执行类型检查共用 `parameterCatalog`；未知参数仍需合法绑定。
  - 验证：空 SQL 可发现并插入参数；修改别名后绑定兼容来源可试跑，缺失或错类型被阻止。

- [x] 任务 3：补完整 SQL 的指标、维度和变体配置链路。
  - 在主配置中开放字段角色修正，允许完整 SQL 同时输出指标和维度，包括数字编码维度。
  - 直接提供的 SQL 显式绑定整体、单维或交叉定义，执行仅包含已配置变体。
  - 保留既有模板生成方式；无对应变体时提示缺少 SQL，不套用所有组合、不从汇总推导交叉。
  - 将变体声明、人工定义和运行快照一起固定到发布版本；保留重解析及试跑失效规则。
  - 验证：完整单维 SQL 从粘贴到解析、角色确认、试跑、核对、发布可完成；数字维度及粒度错误有实际校验。

- [x] 任务 4：补下钻元信息与展示门禁。
  - 独立和交叉定义自动生成 Key、名称，说明选填；更多设置中查看 SQL 绑定，校验唯一性、成员数量和成员合法性。
  - 补字段级对照组比较指标“—”展示，保留普通基值及全部 SQL 原值。
  - 发布校验覆盖字段说明、类型、格式、精度和下钻定义完整性；展示修改使核对失效。
  - 验证：交叉成员缺失、重复或输出不匹配不能发布；对照组比较展示与数据快照一致。

- [x] 任务 5：补目录治理与来源操作规则。
  - 能力目录及 SQL 复用管理展示来源、Key、目标、版本与草稿差异、更新时间。
  - 补名称或 Key 搜索及来源、目标、发布状态筛选，包括已归档状态。
  - 内置 SQL 只读、试跑及复制，自定义 SQL 可编辑；共用入口保护内置 RPC 的来源边界。
  - 补归档确认和引用影响展示，阻止新增选择归档对象，保留已有固定引用。
  - 验证：列表状态随定义变化正确更新；直接触发操作也不能修改内置定义；归档后已有引用仍可读取。

- [x] 任务 6：补稳定 Key、基础信息及试跑版本记录。
  - 补平台业务目标与负责人邮箱前缀校验；SQL 子项沿用能力组基础信息。
  - 首次显式保存后稳定 Key，显式修改展示当前引用影响并二次确认；取消不改草稿。
  - 试跑记录补当前对象范围说明；版本补操作、操作人、时间。
  - 验证：重命名不改 Key；手动改 Key 不修改旧发布版本或分析引用；试跑不产生未发布定义差异。

- [x] 任务 7：验证完整原型链路并更新验收状态。
  - 逐项执行 `checklist.md` 的原型验收；对变体执行、粒度和版本隔离使用实际示例结果校验。
  - 回归现有四种指标维度组合、独立与交叉下钻、能力内草稿发布和独立 SQL 跨组复用。
  - 检查空数据、执行失败、权限不足、类型错误、重复粒度、发布失败与修改后验证失效。
  - 执行 `npm run build`，浏览器验证关键链路与刷新后的草稿、版本、记录保留。
  - 仅在出现行为问题时补针对性验证，避免为纯展示修改编写镜像测试。
  - 将通过项目勾选，失败项目转为修复任务；原型验收不勾选为生产接入完成。

验收记录（2026-10-21）：本地 SQLite 执行与版本隔离 9 组验证通过；Playwright 实际页面 8 组验证通过，覆盖参数、联合 SQL、Key 确认、能力发布与分析、比较展示、管理筛选与归档、内置来源、刷新和窄屏。消费力 × 城市查询一次执行、返回 6 行；既有四种来源组合的结果仍为整体 / 两个独立维度 / 交叉的 2 / 6 / 4 / 12 行。`npm run build` 通过。验证脚本和截图仅用于验收，不生成新的离线交付包。

## 依赖与可并行范围

- 任务 1 先统一获批规则。
- 任务 2、3、5 在任务 1 后无业务依赖，可由不同子代理并行；共享文件编辑需协调职责或使用隔离工作区后合并。
- 任务 4 依赖任务 3 的变体和成员定义。
- 任务 6 依赖任务 3、5 的引用及对象状态定义。
- 任务 7 依赖任务 2–6 完成。
- 在现有工程增量修改并验证，任务完成后同步勾选状态。

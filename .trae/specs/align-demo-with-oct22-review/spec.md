## 新增需求

### 需求 R03：可编辑的解析及 AI 生成结果

系统应在完整 SQL 静态校验通过后提供指标与维度两类定义。AI 辅助产出名称、类型建议与描述；输出字段 Key 与真实 SQL 输出关系明确，创建者能够修正角色、名称、类型与描述。生成的字段定义不能代替 SQL 语法或结构校验。SQL 拆分过程不在前端 Demo 中呈现。

#### 场景：第一次生成配置

- **WHEN** 创建者提交一套包含指标与维度的完整 SQL。
- **THEN** 系统显示本次生成状态，成功后展示两类结果及其对应字段，允许直接编辑名称、类型和描述；解析和生成不创建试跑或发布记录。

#### 场景：名称、类型或角色需要修正

- **WHEN** 数字城市 ID 被识别为指标，或者 AI 的名称、描述不正确。
- **THEN** 创建者可将该实际输出设为维度并修正定义；角色变化更新可组合成员，不修改 SQL 原值。

#### 场景：生成失败或返回过期结果

- **WHEN** 生成失败，或者生成期间完整 SQL 已改变。
- **THEN** 系统保留当前 SQL 与人工设置，给出可重试反馈；过期响应不能覆盖新 SQL、人工输入或当前确认状态。

#### 场景：只有本地演示服务

- **WHEN** 未配置真实模型拆分接口。
- **THEN** 使用可说明来源的固定演示配置与执行 SQL 展示交互；在统一演示环境说明中标明模拟边界，不将预设字段映射或字符串改写称为真实 AI 生成。

“约一分钟”来自 S4 00:10:29–00:10:51 的个人试验，不是性能承诺。Demo 不人为阻塞一分钟，不新增专项性能优化或固定超时标准。

### 需求 R04：SQL 拆分不在前端 Demo 呈现

完整 SQL 如何生成单维和交叉查询属于后端实现方案，不是本次前端 Demo 的评审内容。

#### 场景：创建者完成 SQL 解析

- **WHEN** 完整 SQL 已解析出指标和维度。
- **THEN** 前端只展示可编辑的指标、维度定义和交叉维度配置，不展示系统生成的单维／交叉 SQL，不要求创建者逐条确认。

#### 场景：配置交叉维度

- **WHEN** 创建者选择需要的交叉维度。
- **THEN** Demo 保存组合配置并可使用现有示例执行链路试跑；不显示“正在拆分 SQL”“查看生成 SQL”“确认 SQL”或“重新生成”等控件。

#### 场景：发布能力

- **WHEN** 用户按最终确定的发布门禁发布能力。
- **THEN** 不因缺少前端 SQL 拆分确认状态而阻止发布。生产系统中的 AI 拆分、语义正确性和后端确认机制另行设计与验收。

### 需求 R09：创建者编辑权限

系统应在创建时记录执行身份作为创建者，不新增“负责人”或可填写的创建者表单。创建者可以修改自己未归档的能力及其所属 SQL，其他可访问模块的用户只能查看与试跑。发布、归档、载入覆盖和改动 SQL 均属于修改操作。

#### 场景：创建者编辑

- **WHEN** 当前身份是该自定义能力创建者，且对象未归档。
- **THEN** 目录显示“编辑”，可修改完整 SQL、输出、组合及草稿，并在满足定义条件后发布。

#### 场景：其他用户查看与试跑

- **WHEN** 当前身份不是创建者。
- **THEN** 目录显示“查看”，定义、绑定 SQL 与已有记录只读；可以按已确认的可用定义试跑。不能通过直接路由、事件处理或载入功能修改原能力。

#### 场景：复制或载入到自己新建的能力

- **WHEN** 用户把允许读取的完整能力内容复制／载入自己的新草稿。
- **THEN** 原能力不变，目标使用目标创建身份、新的内部 ID 与首次保存生成的 Key，不继承来源历史、发布或确认凭据。

#### 场景：旧数据没有创建者

- **WHEN** 既有草稿或发布数据未存创建身份。
- **THEN** 不凭名称或操作记录推断真实所有权；使用明确的本地兼容策略，策略见 Q4。原型身份切换放在已有演示环境设置中，不建设登录系统。

前端权限演示不构成生产授权。真实写操作需要服务端按创建身份判定，本期不扩展到部门、角色树、审批或个人底表权限矩阵。

### 需求 R10：服务身份取数与权限失败

系统取数应统一走服务身份，而非用户个人表权限。服务尚无某张表的权限时，运行失败并说明缺失服务表权限；用户修正 SQL 或服务完成授权后可重试。

#### 场景：服务拥有表权限

- **WHEN** 可访问模块的用户试跑，且服务可读取 SQL 涉及的数据表。
- **THEN** 使用同一服务身份执行，不要求用户先选择个人授权模式或申请个人底表权限。

#### 场景：SQL 引入服务尚未授权的新表

- **WHEN** 执行接口返回服务无权读取该表。
- **THEN** 记录该轮权限失败，提示“服务尚未取得该数据表权限”及接口返回的可用信息；不自动申请权限、不切换为个人身份、不把旧成功结果当作本次结果。

具体 PSM、权限申请地址、生产错误码与联系人为 `[TBD]`。Demo 保留权限失败模拟，真实权限申请不属于本轮操作。

### 需求 R12：报告上下文中的 AI 追问 Demo

系统应在当前模块的分析输出上下文提供小型“AI 追问”入口，打开对话区，自由输入问题并查看多轮回答。首版不预置固定问题类型、skill 配置器或问题范围选择器。

当前工程没有独立正式报告页，实施建议是在 `#/analysis/:attemptId` 承接报告内追问交互，作为模块当前输出的演示；不为该功能建设报告中心或将试跑记录转换为正式报告。

#### 场景：基于当前输出发起追问

- **WHEN** 当前输出已完成，用户打开追问并输入问题。
- **THEN** 演示请求使用当前输出的全量报告上下文，包括实验与观测范围、能力版本、分析配置、全部结论、判断边界和全部证据数据；不能只传当前可见卡片或选中的一行。

#### 场景：追问同一报告

- **WHEN** 用户继续提问。
- **THEN** 会话沿用该报告上下文及本会话已有对话，显示用户问题、生成状态和回答，不更改原报告结论或取数定义。

#### 场景：切换报告或生成失败

- **WHEN** 切换到另一次分析输出，或者追问请求失败。
- **THEN** 新输出不混入旧报告内容及会话；失败可重试同一问题，不重新取数、不重新发布能力。

#### 场景：未有完整报告或模型未接通

- **WHEN** 输出运行中、失败，或者真实模型接口未配置。
- **THEN** 没有完整报告时提示完成分析后再追问；模型未接通时以明确的上下文演示适配展示交互，不声称真实模型回答、真实模型选型或模型自动拒绝所有无关问题。

会话保存期限、服务端历史管理、引用高亮／选中文本追问均未定稿；本轮采用本会话内对话即可，见 Q5。模型选择与申请仍为生产依赖，周五 2026-10-23 评审 Demo，不承诺下周强制上线。

## 修改的需求

### 需求 R01：完整 SQL 的单一主流程

系统新建自定义取数能力应使用基础信息和一套完整 SQL 定义指标及维度。完整 SQL 可以包含多个实际指标、多个维度和计算表达式；本期不要求分别编写指标 SQL、维度映射 SQL，也不提供钱效指标与自定义维度的拼接配置。

#### 场景：新建能力

- **WHEN** 用户点击“新建取数能力”。
- **THEN** 填写名称、说明与固定业务目标后，在同一能力上下文编写完整 SQL，完成解析、维度和组合确认并保存；不先进入已有指标库或独立 SQL 发布。

#### 场景：载入已有完整能力

- **WHEN** 创建者使用现有“载入已有取数能力”。
- **THEN** 沿用最新已发布定义优先、否则已保存草稿、替换确认及目标信息保留的规则；新流程的数据也应能完整载入，不破坏来源定义和固定分析引用。

#### 场景：读取旧复杂配置

- **WHEN** 旧能力含多来源、独立计算指标或枚举条件。
- **THEN** 保留原草稿及已发布版本并按原定义读取、执行；使用兼容视图或明确的迁移选择，不能自动丢字段、改公式或清空历史。兼容旧定义不等于在新建流程继续开放旧入口。

### 需求 R02：参数目录前置

系统应在写 SQL 前直接展示可用实验上下文，支持查看含义、类型和占位符，复制或插入 SQL。输入实际实验 ID 和时间仍发生在试跑浮层；解析后的入参绑定默认收起，发现未绑定或类型不匹配时才展开。

#### 场景：尚未编写 SQL

- **WHEN** 用户进入完整 SQL 编辑区。
- **THEN** 不必先解析即可看到可用实验 ID、钱效实验 ID、观测日期等当前目录信息，并可复制／插入占位符。

#### 场景：观察时间与实验时间

- **WHEN** 展示起止时间参数。
- **THEN** 清楚说明当前目录的 `start_date`、`end_date` 是观测窗口；没有服务端定义的实验开始／结束字段不伪装成已经可用，生产目录补充项见 Q2。

### 需求 R05：解析后配置交叉维度

系统应在完整 SQL 的指标、维度确认结果之后展示组合入口。组合只使用同一完整 SQL 已声明的维度成员；普通多选和交叉有明确不同的取数定义，生成的交叉 SQL 随能力发布。

#### 场景：没有可用维度

- **WHEN** SQL 尚未解析、解析失败或没有已确认的维度。
- **THEN** 不渲染三类来源选择器或可操作交叉面板，不展示无用空配置区；整体指标配置仍可继续。

#### 场景：新增交叉

- **WHEN** 创建者在解析结果后选择两个或更多不同维度组合。
- **THEN** 形成显式交叉项并生成对应 SQL；同一组合不重复添加，不自动遍历其他组合。现有 2–4 个成员限制暂沿用，不将这个数字写成会议新增结论。

#### 场景：分析模块使用交叉

- **WHEN** 用户新建／配置分析模块并选择一个能力固定发布版本。
- **THEN** 只选择该版本已经声明且确认的单维／交叉取数项及指标；分析端不新增组合、不调用 AI 临时补一个未发布 SQL。

### 需求 R08：目录来源和操作

本期目录应保留名称、指标数量、来源、发布状态与更新时间，来源展示为内置 RPC 与自定义 SQL，不新增官方／非官方 SQL 属性。编辑或查看由创建身份及旧对象只读规则决定，试跑由现有可执行条件决定。

#### 场景：查看目录

- **WHEN** 用户打开目录或筛选来源。
- **THEN** 新建 SQL 能力采用统一自定义 SQL 标签，不以官方、个人、预置 SQL再拆一层；RPC 保留原类型和交互。底层旧 `builtin_sql` 类型不删除，仅不作为本期新增官方属性。

#### 场景：进入分析

- **WHEN** 用户需要用已发布能力做分析。
- **THEN** 从分析模块新建／配置入口选择固定版本；目录行内不再提供“用于分析”。发布记录里的同名快捷入口是否一起撤下见 Q3，不据目录讨论自动扩大删除范围。

### 需求 R11：从简的发布策略

系统应按审批确定的策略提供基础定义和 SQL 基本语法校验。解析、试跑与发布分清：解析不产生试跑记录，查看不恢复核对，发布保存固定定义，失败不增加版本。

#### 场景：基础配置或绑定不完整

- **WHEN** 名称、目标、说明、实际指标输出、参数来源或已声明粒度缺少有效定义。
- **THEN** 基础检查给出具体缺项，不能发布无执行定义的能力。将这些规则归为“基础校验”是本提案建议，需与 Q1 一并确认。

#### 场景：原始 SQL 语法无效

- **WHEN** 原始完整 SQL 语法检查失败。
- **THEN** 提示修正 SQL；前端 Demo 不增加拆分 SQL 的确认状态或语法门禁。

#### 场景：采用 Q1 建议的最简发布

- **WHEN** Q1 明确采用“基础定义和原始 SQL 语法通过即可发布”，当前没有成功试跑。
- **THEN** 仍可保存并发布固定版本，试跑和结果核对保留为验证工具；未试跑不补造“已验证”或运行 ID。

#### 场景：选择保留强制试跑核对

- **WHEN** Q1 明确要求继续以当前成功试跑及结果核对作为发布前提。
- **THEN** 沿用同查询／核对签名和最新实际结果规则，并在正式规格中写清此额外前提；不能声称会议已经明确只有语法门禁。

### 需求：本期多来源指标、维度拼接

**原因**：本期按完整 SQL 交付，不做钱效指标关联、公共维度预置或跨指标组的维度关联。S2 00:14:22–00:18:23。

**原因**：本期不展示枚举值，也不增加枚举获取流程。S4 00:11:42–00:12:18。

### 需求：目录“用于分析”快捷操作

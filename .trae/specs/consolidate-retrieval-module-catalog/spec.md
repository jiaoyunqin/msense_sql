# 取数能力目录最小收拢 Spec

状态：用户已批准，实施及本地验收完成。变更编号：`consolidate-retrieval-module-catalog`。日期：2026-10-22。

验收：8 组浏览器验证通过，覆盖原卡片尺寸与标题栏位置、来源及联合筛选、搜索与计数、选择／展开保留、配置复用、实际 SQL 试跑、归档恢复、固定版本分析及 390px 窄屏。页面无运行错误，`npm run build` 和 `git diff --check` 通过。仅本地更新，按工作区最新约定未推送 GitHub 或部署 Vercel。

本版本替代此前提案。以交付文档的三种来源标签和来源／业务目标／发布状态筛选为准，同时遵守用户“基本样式不要改动”“直接在我圈选出来的这块区域补充信息”“非必要不添加”的约束。

## 为什么

用户新建的一次完整取数配置就是一个独立取数模块，可以组合多个已有来源。目录按交付文档提供来源标签和筛选，同时保留当前卡片及展开明细的样式和操作。

## 变更内容

* 保留“取数能力”页面和导航、现有模块条目、卡片样式、展开／收起及明细选择。

* 来源标签仅采用内置 RPC（蓝）、内置 SQL（绿）、自定义 SQL（紫），不增加“系统预置／自定义模块”标签。

* 顶部提供来源、业务目标、发布状态三个筛选及原搜索框，不增加模块类型筛选。

* 在用户圈选的标题栏空白区补充来源、版本／草稿状态和更新时间。

* 修正现有条目的筛选匹配与计数，延续名称／Key 和原指标／维度搜索。

* 延续当前新建、编辑、SQL 复制、归档、试跑与发布链路；一次自定义配置仍为一个目录条目。

## 影响

* 受影响能力：来源标签、来源／业务目标／发布状态筛选、标题栏信息、搜索与计数。

* 主要代码范围：`src/main.js`、`src/composer-ui.js`、`src/composer-management.js`；沿用 `src/composer-data.js` 的来源定义。

* 样式范围：`src/composer.css`、`src/style.css` 仅调整新增筛选与标题栏信息的布局，不重设卡片及展开明细样式。

* 实现时同步 `docs/spec.md` 的目录规则；SQL 编辑器、计算、参数绑定、执行引擎及分析逻辑不属于本轮改动。

* 保留当前工作区和无关修改；旧 ID、Key、草稿、发布快照、SQL 归属及分析引用不迁移或重建。

### 对象定义

| 对象        | 定义及目录关系                                                |
| --------- | ------------------------------------------------------ |
| 取数模块      | 当前目录的完整取数配置；一个对象一个条目，沿用来源分类与相应操作规则。                    |
| 用户新建的完整配置 | 对应已有能力组对象，可引用多个已有来源并加入自定义 SQL；按现有对象来源分类为自定义 SQL。       |
| SQL 取数项   | 模块内部的指标／维度来源；继续由配置页和 SQL 复用管理承接，不自动升格为目录模块。            |

来源标签描述目录对象本身的来源分类，每个条目只展示一个来源标签，筛选使用相同来源值。内置 RPC、内置 SQL 读取平台或现有对象元信息；用户新建完整配置沿用 `custom_sql`。内部复用来源继续在配置区域展示，不据此给模块叠加多种来源标签，也不改变整个配置的编辑权限。

## 新增需求

### Requirement: 三种来源标签与来源筛选

系统 SHALL 仅使用内置 RPC（蓝）、内置 SQL（绿）、自定义 SQL（紫）三种来源标签。顶部来源筛选提供全部、内置 RPC、内置 SQL、自定义 SQL，默认全部，标签与筛选共用相同来源分类。

来源为单选，按目录对象的来源分类匹配。来源、业务目标、发布状态和关键词共同生效，条件之间为 AND。筛选只控制目录可见性，不修改模块、选中指标、展开状态或试跑上下文。

#### Scenario: 按来源找模块

* **WHEN** 用户选择来源“内置 RPC”

* **THEN** 只显示来源为内置 RPC 的目录条目，条目使用蓝色内置 RPC 标签，不附加系统预置标签。

#### Scenario: 自定义模块复用内置 SQL

* **WHEN** 用户新建完整配置并复用内置 SQL

* **THEN** 该完整配置沿用自定义 SQL 的紫色标签并可编辑；内部内置 SQL 定义仍只读。模块按“自定义 SQL”来源匹配，不因子项来源而改成内置 SQL。

### Requirement: 业务目标和发布状态筛选

系统 SHALL 在目录顶部提供业务目标下拉，包含全部及平台已有业务目标，不允许自建目标。本期可选项为全部／平台老客提频，默认全部；不编造其他目标。该目录筛选不改变新建配置中固定只读的业务目标。

发布状态下拉提供全部、已发布、有未发布修改、仅草稿、已归档，默认全部。具体匹配规则见“搜索、发布状态与计数一致”。

#### Scenario: 联合筛选

* **WHEN** 用户选择来源“自定义 SQL”、业务目标“平台老客提频”、发布状态“有未发布修改”

* **THEN** 只显示同时满足三项条件的完整配置，标题栏来源和状态与筛选一致。

### Requirement: 圈选标题栏补充必要信息

系统 SHALL 仅在用户圈选的标题栏空白区补充以下信息。已有信息改放到该区域时避免重复；保留标题、已选数量、右侧操作和卡片正文的原功能。

| 信息    | 展示规则                                                             |
| ----- | ---------------------------------------------------------------- |
| 来源    | 仅内置 RPC 蓝、内置 SQL 绿、自定义 SQL 紫；每个目录对象展示一个标签。                       |
| 版本／状态 | 已发布 vN；有真实未发布修改时同时显示“vN+1 草稿待发布”；无发布版本的自定义配置显示“仅草稿”；归档时保留已有归档状态。 |
| 更新时间  | 读取真实保存或定义更新的时间，以次要文字显示；没有元信息则显示“—”，不生成假时间。                       |

来源按目录对象元信息读取，不受本次指标选择、启用维度或内部 SQL 数量影响。空的新建配置仍按自定义 SQL 分类，配置完整性继续由已有校验处理；元信息缺失时沿用已知历史来源适配，不通过指标名称猜测。

标题和右侧按钮保持可读、可用。长信息省略并通过原生悬浮提示提供完整文本；窄屏可在同一标题栏内自然换行，不引入新详情页或抽屉。选择标签或时间不得误触展开。

#### Scenario: 在圈选区域打标

* **WHEN** PreAA 指标卡显示模块信息

* **THEN** 新信息位于“已选 X 个指标”之后、“试跑／展开”之前，卡片边框、圆角、字号及明细布局延续现状。

#### Scenario: 完整配置中引用多个来源

* **WHEN** 用户新建的完整配置同时引用内置 SQL 和自定义 SQL

* **THEN** 目录只显示一个自定义 SQL 标签和一个模块条目；内部来源在原配置页查看。

#### Scenario: 系统元信息缺失

* **WHEN** 当前系统模块没有真实的平台版本或更新时间

* **THEN** 相应位置显示“版本未提供”或“—”；不把原型可查看／试跑等同于已有正式发布版本。

## 修改需求

### Requirement: 列表和明细保持现有交互

系统 SHALL 保留原卡片形态、标题与操作位置、展开／收起方式和当前默认展开规则。展开后说明、指标及维度选择、全选和保存／载入配置继续原位使用；自定义模块沿用现有编辑配置入口，不另造统一详情组件。

原“已选 X 个指标”仍表示本次已选数量，不改成可用指标总数；有多个指标来自一个 SQL 时按实际选中指标计算。筛选后返回全部，原选择和展开状态保持。

#### Scenario: 展开系统模块

* **WHEN** 用户点击原“展开”按钮

* **THEN** 原卡片内显示原指标和维度选择区，可继续选指标、试跑及保存配置；不打开抽屉。

### Requirement: 搜索、发布状态与计数一致

系统 SHALL 让所有目录条目共同遵守来源、业务目标、发布状态和搜索条件。搜索至少支持模块名称或已保存 Key，并保留原指标／维度搜索；系统模块按其提供的字段匹配，自定义按已配置字段匹配。忽略首尾空格和大小写。

发布状态保留全部、已发布、有未发布修改、仅草稿、已归档。全部默认排除归档；已发布包含仍有有效版本但有草稿修改的模块。系统没有发布元信息时在全部状态可见，不冒充已发布、仅草稿或有未发布修改。

沿用已有页面计数位置，显示当前筛选后模块数量。SQL 子项、保存配置和试跑记录不计入；无匹配项沿用空结果提示。保持现有排序，不增加排序控件、分类数量或独立统计区。

#### Scenario: 多条件和空结果

* **WHEN** 来源、业务目标、发布状态和关键词共同筛选

* **THEN** 可见卡片和计数一致；无匹配时显示原空结果提示，不残留上一轮卡片。

#### Scenario: 未选择指标也能搜索系统模块

* **WHEN** 尚未选试跑指标，用户搜索“发券面额”

* **THEN** 可以找到提供该指标的“实验背景与配置”。

### Requirement: 完整模块与来源操作边界延续

系统 SHALL 继续将一次完整自定义配置保存、试跑和发布为一个独立模块；指标和维度可来自不同已有可用来源。保留现有新建取数能力、关联能力组等操作名称，本轮不全站改名。

内置 RPC 只读查看及试跑，不复制为 SQL、不编辑或归档；内置 SQL 只读查看、试跑及已有“复制为自定义 SQL”；自定义配置沿用编辑、试跑、归档／恢复和固定版本用于分析。模块可编辑不代表内置来源可编辑；来源保护继续在操作处理处生效。

不扩展归档、复制、试跑和发布规则，也不为未接入 RPC 补造组合执行能力。仅查看、筛选或试跑不产生发布定义变化。分析继续引用明确的发布版本，归档前确认引用影响，已有固定引用保留。

#### Scenario: 跨来源配置

* **WHEN** 用户在一个自定义配置中选择多个已有来源并加入 SQL

* **THEN** 原配置链路照常完成，目录只显示一个自定义模块，不挂在某一个系统模块下。

#### Scenario: 兼容旧工作区

* **WHEN** 已有草稿、版本和分析引用的浏览器打开更新后的目录

* **THEN** 原数据、Key、选择和引用保持；补充来源标签和筛选不会触发“草稿待发布”。

## 从上一版提案中移除

这些项目尚未实施，是撤回提案范围，不是删除已有产品功能：

* “系统预置／自定义模块”标签及“全部模块／系统预置／自定义模块”类型筛选。

* 根据内部引用推导多来源标签和混合来源匹配。

* 表格式管理列表、列表整体改版及单独的移动端条目设计。

* 新详情抽屉，以及把原指标／维度选择迁出卡片。

* 将支付、核销 SQL 模板额外包装为两个新目录模块。

* 整模块复制入口、全站“能力组”改名、页头“更多管理”重排。

* 分类数量、新增配置摘要统计、重置按钮和新排序规则。

本轮仅保留文档要求的三种来源标签、来源／业务目标／发布状态筛选、圈选区域的元信息和目录一致性。继续维护现有工程与预览，不生成新离线 HTML 或源码包。

# 2.2 分析模块计算指标 Spec

状态：2026-11-08 已实现并完成本地验收。三列配置、模块试跑及多实验报告计算结果已接入 Demo；主规格已同步。

## 为什么（Why）

分析师已经在实验分析模块中选择了取数能力，需要直接用这些能力提供的指标完成基础计算，并把计算结果用于当前模块的分析和报告。

## 变更内容（What Changes）

- 在取数能力卡片之后、分析思路之前，新增“计算指标（可选）”。
- 参考 Libra 的行内表格，主界面仅保留“指标名称、计算类型、表达式”，就地添加、编辑、删除。
- 计算类型为相加、相减、相乘、相除；表达式通过选择“指标 A”和“指标 B／数值”组成，运算符由类型自动带出。
- 指标只能来自当前模块已选取数能力，选择尚未勾选的指标时同步加入取数范围。
- 每个实验、实验分组与数据粒度分别计算，结果随模块版本及报告快照保存。
- 本次提案不修改原始取数能力定义，也不增加全局计算指标库。

用户确认参考 Libra 简化后接入 Demo。本文三列交互及来源范围、数据校验和快照规则已实现，验收依据见 checklist.md。

## 影响范围（Impact）

- 受影响规格：实验分析模块配置、模块试跑、发布快照、单实验及多实验报告中的模块数据。
- 预期涉及代码：`src/analysis-modules-ui.js`、`src/analysis-modules.css`、`src/analysis-module-data.js`、`src/analysis-module-runner.js`、`src/multi-experiment-data.js`、`src/multi-report-content.js`、`src/multi-experiment-report.js`；计算逻辑宜独立为小型模块。
- 当前事实来源为 `docs/spec.md`；页面及执行链路完成验收后再同步已实现规则。
- 已检查既有规格：SQL MMVP、10 月评审规格中的计算指标条目讨论的是 SQL/取数能力编辑侧的独立配置器；模块试跑记录与报告展示规格也未涵盖本需求。因此新增独立 change-id，不恢复这些旧任务。
- 现有模块和已发布报告默认没有计算指标，继续原有行为；历史版本不自动补算。

## 新增需求（ADDED Requirements）

### CM-01：入口与页面顺序

桌面页面保留最近确认的顺序：

1. 模块名称、模块说明。
2. 业务目标、适用端。
3. 分析类型。
4. 取数模块及已选能力卡片。
5. **计算指标（可选）**。
6. 分析思路、注意事项。

未选择取数能力时不展开空配置区。选定能力后显示轻量标题与“＋添加计算指标”；无可计算的数值指标时禁用添加，并提示“当前取数能力暂无可计算指标”。用户没有添加计算指标时，不影响原有保存、试跑和发布流程。

#### 场景：添加一条计算指标

- **WHEN** 点击“添加计算指标”
- **THEN** 在本页追加一行“指标名称、计算类型、表达式”，不跳转新页面；配置保存在当前模块草稿，沿用页头保存/发布操作。

### CM-02：最简配置

| 主界面字段 | 简化方案 |
| --- | --- |
| 指标名称 | 输入新计算指标的名称；必填，当前模块内不重复，例如“用户核销率” |
| 计算类型 | 下拉选择相加（A+B）、相减（A−B）、相乘（A×B）、相除（A÷B）；默认相除 |
| 表达式 | 两个可搜索的指标选择框，运算符由计算类型自动带出；第二项可切换为固定数值 |
| 操作 | 行内编辑、删除；“更多”收纳低频展示设置 |

表达式示意：`[核销用户数 ▾] ÷ [领券用户数 ▾]`。选择指标时按取数能力分组，所属能力用于区分同名指标。用户填入的是已有指标或数值，不必手写指标 Key 或完整 SQL。

主表不重复增加运算符选择，也不摊开展示精度、指标 Key、来源版本等配置。默认显示数值、保留两位小数、在报告中展示；“更多”可切换数值／百分比、调整 0–6 位小数及报告展示开关。删除计算定义不自动取消其原始指标的取数勾选。

只参考 Libra 的行内配置方式。本层使用取数能力已输出的指标值，首版不重复提供 SUM、UV、人天等聚合选项；“A／进组用户数”可直接选择已有的“进组用户数”指标作为分母，无需单独增加计算类型或隐式取数。

示例：假设当前模块已选择“领券核销整体情况”，新增“用户核销率”，公式为“核销用户数 ÷ 领券用户数”，显示格式设为百分比。示意输入 2,000 和 10,000，原始结果为 0.2，展示 20.00%；百分比格式不要求公式再乘 100。

首版不提供任意 SQL、脚本、自由输入的复杂表达式、聚合函数、括号嵌套或计算指标之间的引用。一个公式包含两个操作数，第一项为指标；第二个可以切换为固定数值。多条公式相互独立。

#### 场景：切换计算类型

- **WHEN** 用户将“相除（A÷B）”切换为“相减（A−B）”
- **THEN** 已选的两个输入保持不变，表达式自动替换运算符；不用再配置一次运算符。

### CM-03：只能引用本模块已选能力

可选集合来自当前模块引用的能力固定版本，只包含可计算的数值型指标。不出现其他模块、未选能力、维度字段、文本配置项或显著性标签。

这里按用户原意限制到“已选能力内的指标”，不额外缩小为“当前已勾选的少数指标”。选择尚未勾选的合法指标时，同步将其加入该能力的取数勾选，并以“已加入取数指标”给予反馈。它不会自动添加新的取数能力。

引用身份使用来源实例、能力固定版本和指标 Key；名称用于展示，不用同名字段推断引用。能力“报告中展示”关闭时，只影响原始数据展示，仍可作为公式输入。

#### 场景：选择未勾选指标

- **WHEN** 已选能力有 8 个指标，当前勾选 3 个，公式选中其中尚未勾选的第 4 个数值指标
- **THEN** 该指标进入公式，并同步成为上方能力卡片的已选取数指标；其余能力不被加入。

#### 场景：移除公式依赖

- **WHEN** 用户移除取数能力、取消勾选被公式引用的指标，或修改引用版本后字段不再存在
- **THEN** 保留公式并标记失效，说明缺少哪个输入；可保存草稿，但不能按失效配置试跑或发布。恢复引用、修改公式或删除公式后重新校验。

### CM-04：按相同实验与粒度逐行计算

使用未格式化的原始数值计算，最后才应用显示格式。原始数据不被改写。

公式在输入指标共同支持、且已选择的粒度上计算。整体、单维、交叉维度分别形成结果，不将整体值与某个分层值直接混算。

跨能力计算只允许已能验证以下条件的组合：相同实验、实验分组、观察窗口、结构化维度定义及维度值，并且每个输入在组合键上唯一。没有兼容的粒度契约时，提示“指标数据粒度无法对齐”，本次不增加关联配置器，也不按同名维度或行号猜测连接。

运行时缺少匹配行、输入为空、除数为零、非数值或非有限结果时，该结果显示“—”并保留具体原因。合法的 0 和负数正常保留，不补零、不自动汇总修正重复数据。结果不自动带上增幅、显著性或统计结论。

#### 场景：多实验计算

- **WHEN** 当前模块分析三个实验
- **THEN** 同一公式分别计算三个实验各自的数据；用户切换实验时看到对应结果，不把不同实验的输入放进同一公式。

#### 场景：除零或粒度不匹配

- **WHEN** 某行分母为 0
- **THEN** 该行显示“—（分母为 0）”，其他有效行继续计算。
- **WHEN** 两个指标没有可确认的共同粒度
- **THEN** 公式校验失败并说明原因，不生成看似有效的值。

### CM-05：试跑与报告展示

计算使用现有模块整体试跑，不增加独立取数或计算任务入口。单能力试跑仍只检查该能力原始结果；涉及多个能力的公式由模块整体试跑验证。

模块整体试跑及报告在原始数据之后增加“计算指标”数据集；不同粒度分表，展示分组/维度与计算值。表头可查看计算公式与输入来源。报告数据集只包含勾选“报告中展示”的计算指标。

计算结果可供当前模块的分析逻辑使用，仍遵循原来的解释边界。多实验报告中，计算值属于选中实验的模块数据；多实验分析结论不得通过跨实验相加或相除得到。

### CM-06：配置与版本

定义随模块保存、复制和发布；发布后固定公式、引用版本、格式与显示设置。复制模块需同步重映射公式的来源实例引用，不继续指向原模块对象。

修改公式或输入定义使当前配置的旧试跑结果失效。历史报告读取当次保存的公式和数值，不以当前草稿重算。计算指标 Key 由系统生成，不新增手填 Key。

## 修改需求（MODIFIED Requirements）

### 模块配置完整性

模块没有计算指标时沿用现有校验。存在计算指标时，在现有保存、试跑和发布规则上增加名称、公式完整性、数值类型、依赖范围及粒度兼容性检查。无效配置允许保留草稿，阻止试跑/发布；运行数据中的个别空值或除零以逐行缺失原因展示，不伪造成 0。

旧规格关于不在 SQL 编辑器中新增独立计算配置的约束保持其原范围；本次新增的是实验分析模块中的后置计算。

## 删除需求（REMOVED Requirements）

无。无需删除或迁移现有取数能力、模块、SQL、报告和历史快照。

## 实施前关注点

当前部分内置字段元信息统一声明为数值，但实际包含实验时间、配置文本或显著性标签；实施时必须校正可计算性判定，不能只根据现有 `type` 字段开放选择。跨能力结果也需以实际可验证的粒度契约为准，不把本地模拟覆盖等同于生产已接入。
